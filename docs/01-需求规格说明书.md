# 安心诊聊平台（AXZL）需求规格说明书

## 1 引言

### 1.1 编写目的

本文档是安心诊聊平台（AXZL - An Xin Zhen Liao）的软件需求规格说明书，旨在明确系统的功能需求、非功能需求和约束条件，为系统设计、开发、测试和验收提供依据。本文档适用于项目开发团队、测试团队、指导教师及评审人员。

### 1.2 项目背景

随着"互联网+医疗健康"政策的深入推进和人工智能技术的快速发展，传统医疗服务模式正在经历深刻变革。当前医疗领域面临以下突出问题：

1. **医疗资源分布不均**：优质医疗资源集中在大城市三甲医院，基层和偏远地区患者难以获得及时、专业的医疗咨询服务。
2. **患者就医体验不佳**：挂号难、排队久、问诊时间短等问题长期存在，患者满意度偏低。
3. **健康知识传播不足**：患者缺乏权威、系统的健康知识获取渠道，容易受到虚假医疗信息的误导。
4. **个人健康档案管理分散**：患者的健康数据分散在不同医疗机构，缺乏统一的个人健康档案管理平台。

基于上述背景，本项目提出建设"安心诊聊平台"，利用大语言模型（LLM）和检索增强生成（RAG）技术，构建一个集智能问诊、健康档案管理、用药提醒于一体的医疗健康服务平台。

### 1.3 术语定义

| 术语 | 说明 |
|------|------|

## 2 系统概述

### 2.1 系统目标

安心诊聊平台旨在建设一个面向医疗场景的智能问诊与健康管理服务系统，具体目标包括：

1. **智能问诊**：基于RAG技术，结合医学知识库和用户健康档案，提供个性化、专业化的AI辅助问诊服务。
2. **知识库管理**：支持医疗文档的上传、解析、向量化和语义检索，构建结构化的医学知识库。
3. **健康档案管理**：为每位用户建立个人健康档案，记录基本信息、过敏史、既往病史、家族病史等，作为问诊上下文自动注入。
4. **用药提醒**：帮助用户管理日常用药计划，支持用药打卡和今日提醒功能。
5. **多角色管理**：支持超级管理员、医疗专家、普通医生、护士助理、患者五种角色，实现精细化权限控制。
6. **AI模型管理**：支持动态配置和切换多种AI大模型（DeepSeek、GPT-4o、Claude等），无需重启即可生效。

### 2.2 用户角色

| 角色 | 角色标识 | 说明 |
|------|---------|------|
| 超级管理员 | admin | 系统最高权限，可管理所有模块和功能 |
| 医疗专家 | medical_expert | 具备知识库管理、文档管理、问诊记录管理等完整业务权限 |
| 普通医生 | doctor | 可进行智能问诊、查看知识库、管理健康档案 |
| 护士助理 | nurse_assistant | 可查看问诊记录、查询健康档案，协助医生工作 |
| 患者 | patient | 可使用智能问诊、管理个人健康档案、使用用药提醒 |

### 2.3 系统边界

本系统包含以下边界：

- **前端**：Vue 3单页应用，包含管理端布局和患者端布局
- **后端**：Spring Boot多模块应用，包含Web层、业务层、框架层、系统层和通用层
- **外部依赖**：DeepSeek API（或其他LLM）、Milvus向量数据库、MySQL数据库、Redis缓存、BGE嵌入模型服务
- **不包含**：线下诊疗、处方开具、药品配送、医保结算等实际医疗业务流程

## 3 功能需求

### 3.1 用户认证与权限管理

#### 3.1.1 用户登录

- **FR-001**：系统支持用户名+密码方式登录，密码使用BCrypt算法加密存储和验证。
- **FR-002**：登录时需进行验证码校验（可配置开关），验证码使用Kaptcha生成图片验证码。
- **FR-003**：登录成功后，系统生成JWT令牌（HS512签名），存储于Redis中，有效期30分钟（可配置），剩余时间不足20分钟时自动刷新。
- **FR-004**：连续登录失败5次后，账户自动锁定10分钟，锁定状态记录在Redis中。
- **FR-005**：系统记录每次登录的日志信息，包括用户名、IP地址、浏览器类型、操作系统、登录状态等。

#### 3.1.2 用户注册

- **FR-006**：系统支持用户自助注册功能（可配置开关），注册时需校验用户名唯一性。
- **FR-007**：新注册用户默认分配"患者"角色。

#### 3.1.3 动态权限控制

- **FR-008**：系统采用RBAC权限模型，用户与角色为多对多关系，角色与菜单为多对多关系。
- **FR-009**：菜单支持三级结构：目录（M）→ 菜单（C）→ 按钮（F），按钮级权限控制精确到具体操作。
- **FR-010**：前端根据用户权限动态生成路由菜单，无权限的菜单不显示。
- **FR-011**：后端使用`@PreAuthorize`注解进行方法级权限校验，权限表达式格式为`模块:子模块:操作`。

#### 3.1.4 用户管理

- **FR-012**：管理员可对用户进行增删改查操作，支持批量导入导出（Excel格式）。
- **FR-013**：管理员可重置用户密码，初始密码为`123456`。
- **FR-014**：用户可修改个人信息（昵称、邮箱、手机号、性别、头像）和密码。

### 3.2 智能问诊模块

#### 3.2.1 问诊对话

- **FR-015**：患者可通过自然语言描述症状，系统基于RAG技术进行智能问诊回复。
- **FR-016**：问诊流程：用户输入 → 文本向量化（BGE-large-zh-v1.5）→ Milvus向量检索（Top-5，余弦相似度>0.6）→ 结合用户健康档案 → 组装Prompt → 调用大语言模型 → 返回回复。
- **FR-017**：系统支持两种对话模式：同步模式（等待完整回复后返回）和SSE流式模式（逐字推送回复内容）。
- **FR-018**：SSE流式模式下，即使前端断开连接，后端仍继续接收AI回复并持久化存储，确保数据完整性。
- **FR-019**：用户可选择是否启用知识库检索（`useKnowledgeBase`参数），关闭后仅基于对话历史和健康档案进行回复。
- **FR-020**：每次对话自动保存消息记录，包括用户消息和AI回复，AI回复同时记录向量检索结果（JSON格式）。

#### 3.2.2 会话管理

- **FR-021**：每次新对话自动创建会话，使用UUID作为会话标识。
- **FR-022**：会话自动提取标题（基于用户首条消息），记录症状摘要和AI诊断摘要。
- **FR-023**：用户可查看历史会话列表，支持会话重命名、置顶、删除操作。
- **FR-024**：用户可对已完成的会话进行满意度评分（1-5星）。
- **FR-025**：管理员可查看所有用户的会话列表，支持分页查询和批量删除。

#### 3.2.3 健康档案上下文注入

- **FR-026**：问诊时系统自动加载用户健康档案（性别、生日、血型、身高、体重、过敏史、既往病史、家族病史、生活习惯），作为上下文注入Prompt。
- **FR-027**：健康档案信息仅对当前用户和管理员可见，确保隐私安全。

### 3.3 知识库管理模块

#### 3.3.1 知识条目管理

- **FR-028**：管理员和医疗专家可手动录入知识条目，包含问题、答案、分类标签、评分、关联疾病等字段。
- **FR-029**：知识条目支持单条导入Milvus向量库和批量导入所有未处理条目。
- **FR-030**：知识条目支持向量状态追踪（未导入/已导入/失败），可查看Milvus向量ID。

#### 3.3.2 文档管理

- **FR-031**：系统支持上传txt、Word（docx）、PDF、Markdown、JSONL格式的文档，单文件最大10MB。
- **FR-032**：文档上传后触发异步向量化处理流程：文件解析 → 文本提取 → 分块（800字符/块，50字符重叠） → 批量向量化（每批20条） → 存入Milvus和MySQL。
- **FR-033**：小于3000字符的文档整体存储，不做分块处理。
- **FR-034**：文档处理状态实时可查（未处理/处理中/已完成/失败），失败时支持重新处理。
- **FR-035**：文档内容使用Apache PDFBox解析PDF，Apache POI解析Word。

#### 3.3.3 语义搜索

- **FR-036**：系统提供基于向量的语义搜索接口，输入自然语言查询，返回最相似的Top-N知识条目。

### 3.4 健康档案管理模块

- **FR-037**：每位用户可维护一份个人健康档案，包含出生日期、性别、血型、身高、体重、过敏史、既往病史、家族病史、生活习惯等信息。
- **FR-038**：健康档案支持管理员端Excel批量导入导出。
- **FR-039**：患者端自动创建健康档案（如不存在），支持在线编辑。
- **FR-040**：健康档案数据在问诊时自动注入AI对话上下文，实现个性化问诊。

### 3.5 AI模型管理模块

- **FR-041**：系统支持配置多种AI大模型，包括提供商标识、模型名称、API地址、API密钥、模型类型（text/embedding/image/audio）、温度参数、最大Token数等参数。
- **FR-042**：每个模型类型可设置一个默认模型，切换默认模型后立即生效，无需重启。
- **FR-043**：系统使用客户端缓存（ConcurrentHashMap）管理ChatClient和EmbeddingModel实例，支持动态刷新。
- **FR-044**：API密钥使用VARBINARY类型加密存储在数据库中。
- **FR-045**：系统预置6个模型配置：DeepSeek V4-Flash（默认对话）、DeepSeek V4-Pro、BGE-large-zh-v1.5（默认嵌入）、GPT-4o、text-embedding-3-large、Claude 3.7 Sonnet。

### 3.6 用药提醒模块

#### 3.6.1 用药管理

- **FR-046**：患者可添加用药提醒，包含药品名称、剂量、服用频次（每日一次/两次/三次、每周一次、按需服用）、提醒时间（最多4个）、开始日期、结束日期、备注等信息。
- **FR-047**：患者可编辑和删除自己的用药提醒，支持启用/停用状态切换。
- **FR-048**：患者可查看今日待服用的药物列表，显示药品名称、剂量和提醒时间。
- **FR-049**：系统支持按药品名称搜索用药记录。

#### 3.6.2 用药打卡

- **FR-050**：患者可对今日用药进行打卡操作，记录按时服药情况。
- **FR-051**：系统自动记录打卡时间，支持按提醒时间分别打卡。
- **FR-052**：今日用药全部打卡后显示"已完成"状态。

#### 3.6.3 管理端功能

- **FR-053**：管理员可查看所有用户的用药提醒列表，支持分页查询。
- **FR-054**：管理员可删除用户的用药提醒记录。

### 3.7 系统监控模块

- **FR-055**：系统记录所有操作日志，包括模块标题、业务类型、请求方法、操作人员、请求URL、请求参数、返回结果、状态、耗时等。
- **FR-056**：系统记录所有登录日志，包括用户名、IP地址、浏览器、操作系统、登录状态等。
- **FR-057**：管理员可查看在线用户列表，支持强制下线操作。
- **FR-058**：系统提供服务器状态监控（CPU、JVM内存、系统内存）和Redis缓存监控功能。
- **FR-059**：系统提供数据监控（Druid连接池）功能。

### 3.8 系统工具模块

- **FR-060**：系统集成Knife4j（Swagger）API文档，支持在线接口测试。
- **FR-061**：系统支持字典数据管理，用于配置系统枚举值（性别、状态等）。
- **FR-062**：系统支持参数配置管理，用于配置系统运行参数（验证码开关、注册开关等）。

## 7 约束条件

1. **技术栈约束**：后端必须使用Java 21 + Spring Boot 4.0.3 + Spring AI 2.0.0-M3，前端必须使用Vue 3 + Vite 6。
2. **数据库约束**：必须使用MySQL 8.0作为关系型数据库，Milvus作为向量数据库。
3. **部署约束**：系统通过Docker Compose提供容器化部署方案，包含所有依赖服务。
4. **合规约束**：系统为AI辅助问诊工具，不替代真实医生诊断，需在界面显著位置提示用户。
5. **网络约束**：系统需要能够访问DeepSeek API（api.deepseek.com），或配置其他兼容的LLM服务。
